# 시설안전 점검 이력관리 1.2.0

## 실행

독립 실행은 `index.html` 또는 별도로 제공한 `시설안전_점검이력관리.html`을 Chrome·Edge에서 여세요. 인터넷 연결과 설치 없이 작동합니다.

## 이번 수정

- 근거 매뉴얼 패널과 내장 원문 PDF를 제거했습니다.
- 메뉴는 현황 대시보드 / PDF·평가표 등록 / 지적사항 이력 / 출력·결과보고 네 개입니다.
- 맞춤 점검표와 자료·백업·통합 메뉴, 직접 지적사항 등록 버튼을 제거했습니다.
- PDF를 선택하면 별도 읽기 버튼 없이 즉시 읽고 ④ 항목별 점검결과를 반영합니다.
- 점검결과 이행→평가 양호, 미이행→평가 미흡, 해당없음→평가 해당없음으로 자동 연결합니다.
- 원문에 결과가 없는 항목은 미확인으로 남깁니다. 원문 평가결과만 읽힌 경우 그 결과에 대응하는 점검결과를 표시합니다.
- 원문 점검결과와 평가결과가 상충하면 원문 평가결과와 대조 안내를 표시합니다.
- 미이행 항목에서만 개선 전후 사진을 첨부할 수 있습니다. 사진은 PDF·평가항목 ID에 연결됩니다.
- 누적 지적사항은 첨부 PDF의 점검결과가 미이행이거나 원문 관리감독자 평가결과가 미흡인 항목만 생성됩니다.
- 같은 표준항목·같은 위치가 반복되면 기존 이력에 자동 연결합니다. 별개 지적은 신규로 선택할 수 있습니다.
- 출력은 등록된 평가표 PDF를 하나 선택해 그 평가표의 결과와 사진, 연결된 개선조치만 반영합니다. 첨부 기록이 없으면 출력하지 않습니다.

## 사용 순서

1. PDF·평가표 등록에서 작성된 PDF를 첨부합니다.
2. 자동 반영된 결과를 확인합니다. 스캔본 또는 다른 형식에서 인식하지 못한 항목은 직접 선택합니다.
3. 점검명·점검기간·담당자·기한을 입력합니다. 미이행 항목의 위치와 계획도 보완합니다. 위치를 비워 저장하면 ‘평가표 N번’으로 구분되므로 실제 위치를 입력하는 것이 좋습니다.
4. 필요한 항목에 개선 전·개선 후 사진을 넣습니다. 원문 대조 확인 후 저장합니다.
5. 미이행·미흡 항목은 이력 화면에서 조치상태·보류·재확인을 관리합니다. 완료하려면 개선 후 사진·재확인일·확인자·확인 체크가 필요합니다.
6. 저장된 평가표를 펼쳐 ‘결과·사진 확인 및 추가’에서 미이행 항목의 사진을 나중에 추가할 수 있습니다.
7. 출력·결과보고에서 첨부 PDF를 선택하고 인쇄하거나 PDF로 저장합니다.

PDF 읽기는 텍스트형 평가표의 연번·결과 열 좌표를 활용한 로컬 분석입니다. OCR·생성형 AI 서버는 연결하지 않습니다. 스캔본, 글꼴 정보가 없는 PDF, 표가 다른 PDF는 일부 또는 전체 인식이 안 될 수 있습니다. 담당자가 원문을 대조해야 합니다. 사진은 긴 변 1600px 이하 JPEG로 저장되므로 원본은 따로 보관하세요.

PDF·사진·변경 이력은 이 기기의 브라우저에 저장되며 자동 공유되지 않습니다. 화면 알림은 앱을 열 때 확인하는 방식입니다. 출력 문서는 원본 PDF를 수정한 파일이 아니라 별도 결과보고서입니다.

## 통합 파일

| 파일 | 역할 |
|---|---|
| index.html | 원문 매뉴얼을 제외한 단일 실행 HTML |
| module.js | 독립 모듈 코드 |
| assets.js | 로컬 PDF 읽기·표시 도구만 포함 |
| standard-items.json | 첨부 평가표 기준 21개 표준항목 |
| integration-example.html | 다른 HTML에 기능을 연결하는 예제 |
| THIRD_PARTY_NOTICES.txt | PDF.js 라이선스 |

통합용 API는 유지하되 화면에는 표시하지 않습니다. Shadow DOM으로 다른 기능의 CSS와 분리됩니다.

```javascript
const safety = SchoolSafetyHistory.mount(container, {
  storageKey: 'school-safety-history-v1',
  schoolName: '우리 학교',
  assets: SchoolSafetyAssets
});
await safety.ready;
const data = safety.exportData();
await safety.importData(data); // 전체 교체
await safety.setSchool('학교명');
container.addEventListener('school-safety:changed', event => {
  console.log(event.detail);
});
```

스키마 버전은 기존과 같은 1이며 `documents / evaluations / issues` 구조를 사용합니다. `evaluations.rows`에 `grade / rawGrade / photos`가 추가됩니다. 사진의 `evaluationId`로 첨부 PDF별 출력 범위를 분리합니다. 미이행·미흡 발견 이력에는 `evaluationId / documentId / itemId` 관계를 유지합니다.

기존 저장소 이름을 유지합니다. 이전 버전의 직접 등록·평가표에 연결되지 않은 지적사항은 새 화면의 누적 이력에서 제외합니다. 원래 파일의 이전 버전은 별도로 남습니다. 여러 화면의 동시 편집은 지원하지 않습니다. 인증·서버 저장·공동 사용·외부 알림은 통합 담당자가 별도로 연결해야 합니다.

## 동작 확인

자동 결과 읽기와 평가 매핑, 미이행 사진 저장, PDF 기반 이력만 생성, 저장 후 사진 추가, 개선 완료와 사진 동기화, 반복 미이행의 기존 이력 연결, PDF별 보고서 범위, 새로고침 후 보존, 모바일 배치와 file:// 실행을 Chromium에서 확인했습니다. 제공 평가표의 19개 결과를 읽고 빈 20·21번은 미확인으로 남기는 동작도 확인했습니다.

## 대시보드 미개선 집계

미개선 카드는 미조치·진행중·보류 3열 표로 표시하며 각 상태의 현재 건수를 ‘N건’으로 보여줍니다. 개선완료는 이 표에서 제외하며 상태를 저장하면 건수도 갱신됩니다.
